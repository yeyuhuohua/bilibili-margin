# 高刷新率与交互性能优化（本地验证）

## 范围与状态

- 基线：`f48f093ea783367dd38e7b3168fd54e891a75123`，版本 `0.60.0`。
- 本地工作分支：`perf/local-high-refresh`。本次不提交、不推送、不创建 PR、不发布版本。
- 目标：减少主线程布局、重复 DOM 扫描和不必要的绘制，使动画能利用约 100 Hz 及更高刷新率；保留现有视觉效果与交互。
- 扩展版本、权限和后台 service worker 未修改。

100 fps 对应约 10 ms 的一帧预算。正常动画采用浏览器原生 `requestAnimationFrame` 节拍：100 Hz 每秒最多约 100 次更新，120/144 Hz 使用各自的均匀节拍。没有在 144 Hz 上硬凑 100 fps，以免产生交替长短帧。实际显示帧率仍取决于屏幕、浏览器、GPU、B 站页面及同时运行的任务。

## 代码改动

### 背景调度与流光

`src/content/bg/background.ts` 移除正常状态与恢复路径的 60 fps 人工上限，保留主动限帧、持续负载过高时降至 30 fps、隐藏暂停和持续健康后恢复。主动 30 fps 上限不会被当成过载；暂停和解除上限时重置旧的绘制间隔。

同时修复两个原有恢复问题：压力计数长期累积导致恢复过慢；100 Hz 上 30 fps 正常出现的 40 ms 间隔被旧恢复条件排除。检测参考 CPU 提交耗时及 rAF 间隔，CPU 提交耗时不代表完整 GPU 耗时。

`src/content/bg/flux/` 将拖尾衰减、速度阻尼和粒子亮度注入按实际经过时间归一化，以原 60 fps 参数为基准。提高刷新率后不会仅因执行次数增加而缩短拖尾、加快阻尼或增亮。长暂停最多推进 100 ms，不追赶整个后台时段。

### 账号卡片

`src/content/ui/user-menu.ts` 与新增的 `user-menu-motion.ts` 保留原 60 Hz Verlet 物理步长，并在显示帧之间插值；翻面与倾斜按时间计算。相同时间的运动进度不再随屏幕刷新率改变。

每帧合并鼠标的最新位置；通过已知卡片几何计算命中范围，缓存头像边界，减少指针移动时的同步布局读取。相同 transform 不重复写入，链条静止且主题未变时不重复绘制。关闭、隐藏和中止手势时清理动画循环与拖拽状态。

物理插值会带来至多一个物理步、约 16.7 ms 的模拟显示延迟；拖拽末端直接使用最新指针位置。链条运动时继续使用原来的珠子渐变，未削减视觉效果。

### 滚动刻度和入场转场

`src/content/styles/07-overlays.css` 将 51 根刻度的宽度动画改为固定宽度上的 `scaleX`，保留原有长度、间距、缓动和错峰延迟。`scroll-ruler.ts` 只在百分比改变时更新标签。

`src/content/ui/intro/intro.ts` 改用一次初始尺寸读取和 `ResizeObserver` 缓存，避免每帧读取 `clientWidth/clientHeight`。连续掉帧时仍自适应降低绘图分辨率；尺寸变化、跳过及结束时正确清理观察器和回调。

另修复软件渲染或无 WebGL 时的提前退出错误：原实现延迟清理会访问尚未初始化的 `renderer`，留下开场遮罩。现在该路径能正常结束并移除遮罩。

### 评论区

`src/content/ui/comment-skin.ts` 在 Shadow DOM 新增评论时只扫描新增子树，同时保留迟到 Shadow Root 的补偿扫描。回复父项查找使用 Map，最坏复杂度由 O(n²) 降为 O(n)；深度优先排序使用显式栈，避免深链递归溢出。

相同 `order` 和缩进标记不重复写入。保留最近一条前置同名作者的匹配语义、原生 DOM 节点顺序、旧新版评论支持，以及最多三层视觉缩进。

## 测试环境与证据边界

本次在 Linux 容器内使用 Chromium `153.0.8010.0` headless shell 和 SwiftShader 软件渲染。实际原生 rAF 间隔约 16.7 ms，不能在此环境验收物理屏幕的 100 fps。

完整 Chrome 的扩展启动被运行环境的进程单实例 socket 权限阻断。因此没有把以下检查称为完整扩展端到端测试：内容脚本集成使用真实 DOM、实际构建的 `content.js` 和页面分块，但替换了 `chrome.storage/runtime` 与 B 站网络响应。它不验证真实账号、线上 API、service worker、扩展隔离世界或权限加载。

### 调度器：模拟时钟，非 GPU 帧率

使用实际背景调度器，替换帧时钟和绘制函数，每阶段三秒。

| 模拟刷新率 | 原版正常绘制次数 | 优化后正常绘制次数 | 优化后主动 30 fps 上限 |
| --- | ---: | ---: | ---: |
| 60 Hz | 180 | 180 | 90 |
| 100 Hz | 180 | 300 | 90 |
| 120 Hz | 180 | 360 | 90 |
| 144 Hz | 180 | 432 | 90 |
| 165 Hz | 180 | 495 | 90 |
| 240 Hz | 180 | 720 | 90 |

另验证解除上限、暂停恢复、持续昂贵提交、持续丢失回调和健康后恢复。正常及恢复阶段没有调度器额外造成的跳帧。

### 刻度、入场和账号交互：真实浏览器测量

| 检查 | 原版 | 优化后 |
| --- | --- | --- |
| 刻度展开的布局次数，三轮 | 51 / 54 / 54 | 0 / 0 / 0 |
| 最终刻度几何 | 9 / 15 / 18 px，轨道高 251 px | 完全相同，局部截图逐像素一致 |
| 入场动画尺寸读取 | 24 个绘制帧中读 48 次 | 23 个绘制帧中只初始化读取 2 次 |
| 入场画布从 420×280 改为 480×300 | 尺寸正确 | 尺寸正确，跳过后正常清理 |
| 软件或缺失 WebGL 的入场退出 | 延迟回调抛错，遮罩未移除 | 无错误，遮罩正常移除 |

入场测量使用相同操作和等待窗口，原生帧数允许受环境调度影响；减少尺寸读取的结论来自代码路径及读取计数，并非帧率增加的证据。刻度三轮原生帧间隔 P50/P95 仍约 16.7 ms，符合测试环境的约 60 Hz 节拍。

优化版内容脚本的三轮集成均通过悬停、翻面、拖拽释放、关闭后停止更新、重新打开和固定模式检查，浏览器 pageerror 为 0。视频页原生播放器保留，无输入的观测窗口中新旧版均为零布局；没有将本来已无额外工作的路径重复改写。

账号场景的 CPU 总耗时没有显示稳定提速。下表为三轮 CDP `TaskDuration`，单位 ms：

| 计时场景 | 原版三轮 | 优化后三轮 |
| --- | --- | --- |
| 开卡 1.6 秒后，无输入观察 1.6 秒 | 166.80 / 213.74 / 177.76 | 246.14 / 205.80 / 184.79 |
| 24 次指针移动 | 258.99 / 334.89 / 258.54 | 326.91 / 243.67 / 283.82 |

该无输入窗口仍可能包含挂绳的自然摆动，不代表完全停稳后的空闲功耗。新版增加时间一致的物理补步与插值，减少了同步几何读取；当前样本不能分离这些成本和软件渲染环境的噪声，因此不宣称 CPU 总耗时降低或整体 FPS 提升比例。基线第二轮在所有计时窗口结束后的额外翻回正面断言未通过；性能数据在该断言之前已采集，优化版三轮交互断言均通过。

### 验证结论

- `npm run build`：通过，包括 TypeScript 检查和所有生产构建分块。
- `npm run test:unit`：19 个测试文件、195 项测试全部通过；原版为 172 项，新增 23 项覆盖高刷时基、拖尾/阻尼/亮度和卡片几何。
- 背景帧调度、动画布局、内容脚本账号交互、评论真实 DOM 回归：通过。
- `git diff --check`：通过。
- 未验证：真实高刷屏幕的 GPU 呈现帧率、完整扩展加载、线上账号及 API、跨浏览器实机运行。

## 复现

```bash
npm ci
npm run build
npm run test:unit
npm run test:frame-budget
npm run test:animation-performance
npm run test:content-performance
npm run test:comment-performance
```

浏览器测试默认使用 Playwright 的 Chromium，可通过 `CHROMIUM_PATH` 指定可运行的 Chromium。`test:content-performance` 需要先构建 `dist/`。

对照原版时，使用同一个测试脚本指定原版 checkout 或构建目录：

```bash
PERF_SOURCE=/path/to/baseline PERF_BASELINE=1 npm run test:animation-performance
SMOKE_EXT=/path/to/baseline/dist PERF_BASELINE=1 npm run test:content-performance
COMMENT_BASELINE=/path/to/baseline/src/content/ui/comment-skin.ts npm run test:comment-performance
```

`SMOKE_OUT` 可设置动画与内容脚本结果目录；`COMMENT_OUT` 可设置评论结果 JSON 路径。`PERF_BASELINE=1` 关闭针对优化版的性能门槛及账号交互回归，保留同一组测量场景。

## 本地试用

解压测试安装包，在 Chrome 或 Edge 的扩展管理页开启开发者模式，加载含 `manifest.json` 的解压目录。测试时只启用一个 MARGIN 版本，避免商店版和本地版同时处理页面。

在目标高刷屏幕上分别检查：首页滚动、背景切换、账号卡片翻面和拖拽、入场转场、评论展开与主题切换。该版本保留低性能设备的降档机制，不承诺任何设备和场景均锁定 100 fps。
